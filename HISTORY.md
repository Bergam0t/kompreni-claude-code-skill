# 0.1.0

- Add `/kompreni:explain`, a Claude Code skill that explains an agent's changes in the conversation
    - Collects changes from git and the conversation, and separates changes the session didn't make
    - Groups changes by purpose and picks a brief, standard or deep explanation
    - Labels rationale as code, stated or inferred, and reports only tests actually run
- Check code references and quoted snippets before answering
    - Snippets are copied verbatim with a location tag, or marked `illustrative`
    - `skills/explain/scripts/check_refs.py` fails on missing files, out-of-range lines and snippets that don't match the repo or a git ref
- Explain the changes on a branch, in a commit, or since a commit (history mode)
    - New `branch=` (with `onto=`), `commit=` and `since=` arguments; `base=` is removed
    - Draws rationale from commit messages and the pull request (via `gh`), labelled *(commit)* and *(PR #n)*
    - Adds an optional "How it got here" section and a scope note; never changes the checkout
    - Handles already-merged branches (finds the merge commit via the PR) and branch names that are also file names
    - `check_refs.py --ref <git-ref>` checks references against a branch or commit that isn't checked out
- Match explanations to the reader's prior knowledge with `level=`
    - Presets: `new-to-programming` (alias `beginner`), `new-to-language`, `intermediate` (default) and `advanced`, or free text such as `"fluent in R, new to Python"`
    - A "Concepts used here" section explains the constructs, patterns and library APIs the change relies on, each tied to a real line
    - With no `level=`, uses what the user has said about their experience, and names the level used
- Add the optional `kompreni-offer` mod
    - After a turn that edits files, shows a row with depth and level pickers and an Explain button that fills in the command (never submits it, never overwrites a draft)
    - Remembers the chosen depth and level across sessions; `/kompreni-offer` changes settings or turns offers off
    - Listed in the marketplace as a separate, optional plugin
- Explain only what changed since the last explanation in the same conversation
    - New `scope=` argument: `new` (default) covers changes since the previous Kompreni explanation, `all` gives one consolidated explanation of the whole conversation
    - Each session-mode explanation ends with a `Kompreni snapshot:` line; `skills/explain/scripts/snapshot.py` records the working tree as a git tree without touching files, index, branches or stash, so later explanations catch every change, including ones made by shell commands
    - The `kompreni-offer` mod now counts files changed since the last explanation across turns, and resets when an explanation runs by any route
    - The mod gains a Scope picker (since last explanation, or whole conversation) once an explanation has run
    - The mod's `auto` options say what they correspond to
    - The mod's row puts each picker on its own line, with its label on the left and the picker filling the width (mod version 0.1.1)
    - The mod's row now shows whenever Claude isn't working, even before any edits; `/kompreni-offer show=changes` restores showing it only after turns that edit files (mod version 0.1.2)
    - When there's nothing new to explain, the row shrinks to one line with Explain, Dismiss and, after an explanation, Whole conversation
- Add `/kompreni:walkthrough`, which writes a structured, persistent walkthrough of changes as Quarto (`.qmd`) or GitHub-flavoured Markdown (`.md`)
    - Saved to `kompreni/walkthroughs/<date>-<slug>.qmd` (or `out=`), standalone for a reader who wasn't in the conversation
    - Teaches rather than reports: the problem first, one running example traced before and after, annotated excerpts, before/after tabs, a diagram only when the flow changed, and questions with hidden, checked answers (`quiz=off` to omit)
    - `.qmd` when Quarto is installed, otherwise `.md`; `format=` overrides. A `.qmd` is rendered to one self-contained HTML file (gitignored), except inside an existing Quarto project
    - Shares session and history mode, `level=` and `focus=` with explain; covers the whole conversation by default; asks before writing one for a small change
    - Asks before writing up uncommitted changes whether to commit them first, briefly saying why and what it would commit (only the session's own changes, never pushed). If not, the walkthrough carries a visible drift note; committed, pushed tips get GitHub permalinks
    - YAML front matter (`kompreni:` with range, commits, files, level, tests) as the starting point for searchable change history
    - Deep explanations now end by offering the matching walkthrough command
- `check_refs.py` understands Quarto code blocks (`filename="path:lines"` captions, `.illustrative`, `{mermaid}`, annotation markers), errors on executable `{python}` cells, skips YAML front matter, and checks GitHub permalinks at their commit
- Add code tours: `/kompreni:walkthrough code=all`
    - Shows all the substantive changed code with a little context, in call-flow order, explained line by line with Quarto code annotations (`code-annotations: below`, so clicking an explanation highlights its lines)
    - Real line numbers in the margin (`.numberLines startFrom=`), test changes annotated inside collapsed callouts, housekeeping summarised
    - Every block from a file that already existed has Before and After tabs, so the old and new code can be compared in place; Before covers the same whole unit as After, and a pure addition shows the old lines around it. New files and tests have no tabs
    - New `skills/explain/scripts/before_range.py` maps an After block's lines to the old lines through the diff, and prints both blocks' line numbers and changed-line marks
    - `.qmd` only; `code=all` with `format=md` asks which to use
    - The default, `code=key`, keeps the one-to-three key excerpts
- `check_refs.py` checks Quarto code annotations and coverage
    - Errors when a marker has no list item or an item has no marker, when prose comes between a block and its list, when an item has a second paragraph, and when an item starts like a list or heading. Quarto silently drops the first three and fails to render the last
    - Errors when `.numberLines` has no `startFrom` matching the caption's first line
    - Recognises `<!-- <n> -->` (Markdown, HTML) and `/* <n> */` (CSS) markers as well as line comments
    - New `--coverage BASE[..TIP]` lists changed lines that no verbatim snippet shows, as notes, ignoring blank lines
    - Checks Before/After tabsets: exactly the tabs `Before` then `After`, old code (`@<ref>`) only in Before, and a warning for a `group`. With `--coverage`, also notes code-tour blocks that need tabs, and line marks that don't match the diff
    - Accepts dotfile paths (`.gitattributes:1-3`) and ignores a leading `./`, so such files count as shown in `--coverage`
- Before/After tabs in Quarto walkthroughs tint the lines the change touched, and switch independently
    - Yellow for a changed line (it has a similar counterpart in the other tab), green for an added one, red for a removed one; removed lines are tinted, never hidden
    - A `~`, `+` or `−` beside each marked line's number, so the kind doesn't rely on colour; it isn't copied with the code
    - Marked with `changed=`, `added=` and `removed=` in the file's own line numbers, paired by similarity within each diff hunk; a small script in the front matter does the tinting, so there's still one self-contained HTML file and no Quarto extension
    - The tabsets are no longer linked with `group`: switching one resized all the others, and the page jumped
- Add a "Useful elsewhere" section to explanations, walkthroughs and code tours
    - Lessons from the change that apply beyond it: library gotchas met here, patterns worth reusing, and debugging or testing techniques that worked
    - Each item must be tied to this change, transferable, non-obvious at the reader's level and accurate; generic advice is excluded, and the section is left out when nothing qualifies
    - Up to 2 items in a standard explanation, 3 in a deep one, 5 in a full walkthrough; a brief explanation gets at most one sentence
    - Walkthroughs also list the items in the front matter as `kompreni.lessons`, so they can be searched across walkthroughs later
    - New evidence label *(observed)* for what was seen happening in the session, such as an error or a test result
- Rendered Quarto walkthroughs and code tours have a light/dark toggle, and open in the reader's system colour scheme
    - Uses Quarto's `flatly`/`darkly` theme pair with `respect-user-color-scheme`; the toggle sits in the top right and remembers the reader's choice
    - Fixes mermaid diagram colours that Quarto's defaults get wrong: dark blue labels and faint arrows in dark mode, near-black subgraph boxes in both modes
    - Inside an existing Quarto project the walkthrough leaves these settings out, so the site's own theme applies
- Rendered standalone Quarto walkthroughs and code tours are wider
    - The body takes the space Quarto keeps on the left for a sidebar, which a standalone page never has, so long code lines and diagrams fit; the table of contents stays on the right
    - Inside an existing Quarto project the walkthrough leaves this out, so the site's own layout applies
- The `kompreni-offer` mod gains **Walkthrough** and **Code tour** buttons (mod version 0.1.3)
    - They fill in `/kompreni:walkthrough` (with `code=all` for Code tour), with the chosen level, and the depth only if it's `standard` or `deep`; never a scope
    - Shown only when the walkthrough skill is installed, on both the full and the one-line row; never overwrite a draft
    - A session-mode walkthrough, typed or invoked by Claude, now resets the count like an explanation does
- Add a documentation site on GitHub Pages
    - A Compare page shows one real change as an explanation, a walkthrough and a code tour, in tabs; `compare.html#explain`, `#walkthrough` and `#code-tour` link to a tab
    - Install, Usage (with all options), the kompreni-offer mod (with screenshots) and How it works pages
    - Built from `site/` by a GitHub Action on each push to main; the README now keeps the essentials and links to the site
- Inline code in code-tour annotation notes is readable in dark mode
    - Quarto styles inline code only in paragraphs, list items and table cells, so in an annotation note it was white on near-white; the theme-fix `<style>` in the walkthrough front matter now gives it the list-item background of each theme
